# 摇人（加数量）

版本：v2.1

---

## 一、系统概述

摇人（加数量）是为已有兵种增加数量的途径。从玩家已拥有的兵种中选择一个，为其增加新的作战单位。属于**强制阶段，不可跳过**。

---

## 二、触发时机

| 时机 | 触发条件 | 说明 |
|------|----------|------|
| **扩容** | 可配置（如奇数层） | 游戏流程配置触发 |

具体触发由游戏流程的流程条目控制（参考 01 文档第三节）。

---

## 三、选择流程

### 3.1 候选池

- 候选池为玩家**当前已拥有的所有兵种**
- 每个兵种对应一个选项
- **同一回合内不会重复选择已选过的兵种**（去重范围：仅本回合内，跨回合不去重）

### 3.2 展示规则

- 从候选池中**随机抽取最多 3 个**展示给玩家
- 玩家从中**选择 1 个**兵种为其增加数量
- 若候选池**不足 3 个**（即玩家只拥有 1-2 个兵种），则全部展示

### 3.3 候选池不足时的处理

当所有已拥有兵种都被排除后，**重置去重状态**，将所有已拥有的兵种重新加入候选池，正常继续选择。

### 3.4 选择后

- 为选中兵种增加 1 个新单位
- 新增单位的品质**随机生成**
- 新增单位自动继承当前已有的光环效果
- 产生历史记录（见第四节）

---

## 四、历史记录

### 4.1 产生记录

每次选择完成后，产生一条历史记录，包含：发生回合、系统类型、本轮展示了哪些兵种、玩家选中了哪个兵种。

### 4.2 读取记录

- **本系统读取**：初始化候选池时，读取本回合的历史记录，排除已选择的兵种
- **其他系统读取**：流程条目的条件触发可检查本系统的历史

### 4.3 存储位置

统一存储在全局历史日志中，按回合和系统类型索引（参考 01 文档第十节）。

---

## 五、获得内容

选择兵种后，按以下规则获得：

| 内容 | 规则 |
|------|------|
| **新增单位** | 为选中兵种增加新的作战单位 |
| **增加数量** | 每次增加 1 个单位 |
| **单位品质** | 新增单位的品质**随机生成** |
| **光环继承** | 新增单位自动继承当前已有的光环效果 |

---

## 六、弹出优先级

```
摇人（新兵种）40 > 摇人（加数量）35 > 撸铁 30 > 命运 20 > 抉择 10 > 猫市 0
```

加数量摇人在新兵种摇人之后、撸铁之前出现。

## 七、历史记录数据结构（参考第四节）

```
HistoryRecord {
    round:      发生回合（层号）
    system:     "recruitmentAddCat"
    appeared:   [兵种1, 兵种2, 兵种3]     // 本轮展示的兵种
    chosen:     兵种X                      // 玩家选中的兵种
    timestamp:  执行顺序
}
```

---

## 八、去重数据结构（参考 3.1）

去重通过读取历史记录实现。初始化候选池时，需要查询以下数据：

| 查询条件 | 字段 | 说明 |
|----------|------|------|
| `round = 当前回合` | HistoryRecord.round | 限定本回合 |
| `system = "recruitmentAddCat"` | HistoryRecord.system | 限定摇人加数量系统 |
| 取 `chosen` 字段 | HistoryRecord.chosen | 获取已选择的兵种 |

候选池计算：

```
候选池 = 已拥有的兵种 - 本回合已选择的兵种
```

候选池为空时，去掉"本回合已选择的兵种"这一排除条件，重新计算。
