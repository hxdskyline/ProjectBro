# 游戏流程

版本：v2.1

---

## 术语定义

| 术语 | 含义 |
|------|------|
| **局** | 一次完整的新游戏，从开局到通关或失败 |
| **层** | 局内的一个阶段，包含准备阶段和战斗阶段 |
| **流程条目** | 准备阶段中的一个待执行事件（如"第3层出现一次摇人"） |
| **历史记录** | 某系统在某回合执行后产生的记录（出现了什么、选择了什么） |

---

## 一、游戏总览

一局游戏由 **初始选择** + **20 层** 组成。

```
初始选择
  │
  ▼
第1层
  ├── 准备阶段（流程条目依次执行）
  └── 战斗阶段
        │
        ▼
第2层
  ├── 准备阶段
  └── 战斗阶段
        │
        ▼
      ...
        │
        ▼
第20层
  ├── 准备阶段
  └── 战斗阶段
        │
        ▼
  游戏结束（胜利/失败）
```

---

## 二、准备阶段玩法

准备阶段包含以下玩法系统：

| 系统 | 包装名 | 强制性 | 说明 |
|------|--------|--------|------|
| 获得新兵种 | **摇人（新兵种）** | 强制 | 从候选兵种中选择一个加入 |
| 已有兵种增加数量 | **摇人（加数量）** | 强制 | 为已有兵种增加数量 |
| 获得兵种词缀 | **撸铁** | 强制 | 词缀选择的包装 |
| 商店交易 | **猫市** | 非强制 | 自由买卖 |
| 祈愿/祝福 | **命运** | 强制 | 选择兵种 + 效果 + 消耗档位 |
| 随机事件 | **抉择** | 强制 | 二选一，低风险/高风险 |

## 三、流程控制

### 3.1 流程条目

准备阶段由**流程条目列表**驱动。每一条目描述了"哪个系统、在哪一层、出现几次、什么条件下出现"。

一个流程条目包含以下信息：

| 字段 | 含义 |
|------|------|
| **触发回合** | 该事件在哪一层出现 |
| **系统类型** | 哪个系统被触发（摇人新兵种 / 摇人加数量 / 撸铁 / 猫市 / 命运 / 抉择） |
| **弹出优先级** | 同一层有多个事件时，谁先弹出（数字越大越先） |
| **重复次数** | 该事件在本层连续执行几次（默认 1 次） |
| **触发条件** | 满足什么条件才出现（可选，为空则必定出现） |

### 3.2 默认流程配置

以下是标准流程配置（可通过条件触发增减条目）：

| 回合 | 系统 | 优先级 | 次数 | 说明 |
|------|------|--------|------|------|
| 1 | 摇人（新兵种） | 40 | 2 | 开局获得 2 个兵种 |
| 2~19 | 撸铁 | 30 | 1 | 每层 1 次词缀选择 |
| 3,5,7,9,11,13,15,17,19 | 摇人（加数量） | 35 | 1 | 奇数层扩容 |
| 4,8,12,17,20 | 命运 | 20 | 1 | 祈愿 |
| 5,10,15 | 抉择 | 10 | 1 | 随机事件 |
| 10 | 摇人（新兵种） | 40 | 1 | 中途加入第 3 个兵种 |
| 3,6,9,12,15,18 | 猫市 | 0 | 1 | 商店（非强制） |

### 3.3 重复次数

**重复次数**控制同一个系统在同一次弹出中**连续执行几次**。

- 次数 = 1：该系统弹出 1 次，玩家做 1 次选择
- 次数 = 2：该系统连续弹出 2 次，玩家做 2 次独立选择
- 每次执行独立生成选项，互不影响

**示例**：极难通关后，下一层配置撸铁次数 = 2，则撸铁连续弹出 2 次，玩家获得 2 次词缀选择机会。

### 3.4 弹出优先级

同一层有多个流程条目时，按优先级从高到低依次弹出：

```
摇人（新兵种）40 > 摇人（加数量）35 > 撸铁 30 > 命运 20 > 抉择 10 > 猫市 0
同一层按优先级串行弹出，每个系统完成后提供明确反馈，避免连续弹窗疲劳。
```

所有强制条目结束后，若有猫市，玩家可自行选择是否参与。

## 四、条件触发

### 4.1 概述

流程条目可附带**触发条件**。只有当所有条件都满足时，该条目才会被加入本回合的执行队列。

条件为空 = 无条件触发（必定出现）。

### 4.2 条件类型

| 条件类型 | 含义 | 示例 |
|----------|------|------|
| **上一层难度** | 上一回合选择了指定难度时触发 | 上一层选了极难 → 触发 |
| **历史选择** | 历史上某系统做过某选择时触发 | 曾在命运中选择过某祝福 → 触发 |
| **历史触发次数** | 历史上某系统被触发过指定次数时触发 | 撸铁已被触发 3 次以上 → 触发 |
| **回合范围** | 当前回合在指定范围内时触发 | 第 10~15 层之间 → 触发 |
| **拥有兵种** | 拥有指定兵种时触发 | 拥有狸花猫族 → 触发 |

### 4.3 条件求值时机

条件在**每层准备阶段开始时**检查，即决定本层哪些流程条目生效。

### 4.4 示例：极难双倍撸铁

第 N+1 层配置两个撸铁条目：

- **条目 A**：无条件 → 必定出现 1 次撸铁
- **条目 B**：条件"上一层难度 = 极难" → 仅当上一层选了极难时，额外再出现 1 次撸铁

效果：正常情况下每层 1 次撸铁；上一层选了极难则变为 2 次。

### 4.5 示例：条件触发新兵种

第 10 层配置一个摇人（新兵种）条目：

- **条件**：拥有兵种 = 狸花猫族
- 效果：只有当玩家拥有狸花猫族时，第 10 层才会出现新兵种选择

## 五、历史系统

### 5.1 概述

每次系统执行后，都会产生一条**历史记录**，写入全局历史日志。所有系统都可以读取历史记录，用于去重、条件判断、信息展示等。

### 5.2 历史记录内容

每条历史记录包含以下信息：

| 字段 | 含义 |
|------|------|
| **发生回合** | 在第几层产生的 |
| **系统类型** | 哪个系统产生的 |
| **出现内容** | 本轮展示了什么（候选列表） |
| **选择内容** | 玩家选择了什么 |
| **执行顺序** | 同回合内区分先后 |

### 5.3 各系统产生的历史记录

| 系统 | 出现内容 | 选择内容 |
|------|----------|----------|
| 摇人（新兵种） | 本轮展示的 3 个兵种 | 玩家选中的 1 个兵种 |
| 摇人（加数量） | 本轮展示的兵种列表 | 玩家选中的 1 个兵种 |
| 撸铁 | 本轮展示的 4 个选项（3 词缀 + 1 buff） | 玩家选中的 1 个选项 |
| 命运 | 祝愿档次 + 3 条祝福列表 | 玩家选中的档次和祝福 |
| 抉择 | 3 个事件选项 | 玩家选中的 1 个选项 |
| 猫市 | 4 个商品槽位 + 刷新记录 | 购买/出售的商品 |

### 5.4 历史记录的读取

任何系统在初始化时都可以读取历史记录，常见用途：

| 用途 | 说明 |
|------|------|
| **去重** | 摇人排除已出现过的兵种 |
| **条件判断** | 流程条目检查历史条件 |
| **信息展示** | UI 显示历史选择记录 |
| **数据统计** | 局结束时汇总统计 |

### 6.2 敌人属性计算

```
敌人最终属性 = 怪物基础数值 × 当前层系数 × 该层独立调整参数
```

### 6.3 战斗产出

| 产出类型 | 来源 | 说明 |
|----------|------|------|
| 猫粮 | 战斗胜利 | 数量与选择的难度选项绑定 |
| 奇物 | 精英掉落 | 每层独立判定，优先掉落未拥有的 |
| 一次性道具 | 概率掉落 | 每层独立判定 |

## 七、状态转移条件

### 7.1 正常流转

```
初始选择 ──→ 第 1 层准备阶段
第 N 层战斗结束 ──→ 第 N+1 层准备阶段（N < 20）
第 20 层战斗结束 ──→ 游戏胜利（击败 Boss）/ 游戏失败（未击败）
```

### 7.2 失败条件

```
战斗中所有出战兵种全部阵亡 → 战斗失败
  │
  ├─→ 随机损失 1 个出战兵种（全部阵亡）
  └─→ 仅剩 1 个兵种时再失败 → 游戏结束
```

### 7.3 阵亡恢复

```
兵种阵亡 → 下层立即恢复（满血复活）
```

## 八、流程条目数据结构（参考 3.1）

```
FlowEntry {
    round:        触发回合（层号）
    system:       系统类型枚举
    priority:     弹出优先级（数字越大越先出现）
    repeatCount:  重复次数（默认 1）
    conditions:   触发条件列表（可选，为空则无条件触发）
}
```

`system` 枚举值：

| 枚举值 | 对应系统 |
|--------|----------|
| `recruitmentNewTribe` | 摇人（新兵种） |
| `recruitmentAddCat` | 摇人（加数量） |
| `affix` | 撸铁 |
| `shop` | 猫市 |
| `ritual` | 命运 |
| `choice` | 抉择 |

---

## 九、条件触发数据结构（参考 4.2）

```
Condition {
    type:     条件类型枚举
    operator: 比较运算符（=, >=, <=, >, <）
    value:    比较值
}
```

`type` 枚举值：

| 枚举值 | 对应条件 |
|--------|----------|
| `previousRoundDifficulty` | 上一层难度 |
| `historyChoice` | 历史选择 |
| `historyTrigger` | 历史触发次数 |
| `roundRange` | 回合范围 |
| `ownedTribe` | 拥有兵种 |

条件求值逻辑：遍历 `conditions` 列表，所有条件均为 true 时条目生效。

## 十、历史记录数据结构（参考 5.2）

```
HistoryRecord {
    round:      发生回合（层号）
    system:     系统类型枚举（同 FlowEntry.system）
    appeared:   出现内容（List<string>）
    chosen:     选择内容（string 或 null）
    timestamp:  执行顺序（int，同回合内递增）
}
```

存储位置：`PlayerData.historyRecords`（`List<HistoryRecord>`）。

查询方式：按 `round` 和 `system` 过滤，获取指定回合/系统的记录。

## 十一、条件求值示例代码（参考 4.4）

```csharp
// 极难双倍撸铁：第 N+1 层配置两个 affix 条目
// 条目 A：无条件
new FlowEntry { round = N+1, system = "affix", priority = 30, repeatCount = 1, conditions = [] }

// 条目 B：上一层选了极难才触发
new FlowEntry { round = N+1, system = "affix", priority = 30, repeatCount = 1,
    conditions = [new Condition { type = "previousRoundDifficulty", operator = "=", value = "Hard" }] }
```

```csharp
// 历史去重：摇人初始化候选池
var history = PlayerData.historyRecords
    .Where(r => r.round == currentRound && r.system == "recruitmentNewTribe")
    .SelectMany(r => r.appeared);

var candidates = allTribes.Except(ownedTribes).Except(history).ToList();
if (candidates.Count == 0) candidates = allTribes.Except(ownedTribes).ToList(); // 重置
```
